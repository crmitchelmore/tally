# Tally iOS - Future Challenge Display Fix

## Date: 2026-02-08

## Context
Bob reported a bug: when creating a new challenge set to start next month on iOS, it showed as "behind" with "20 days left" instead of indicating it's a future challenge.

## PR #152: fix(ios): show 'Starts in X days' for future challenges
Branch: `fix/future-challenge-display`
Status: All CI checks passing except Android UI Tests (Espresso) which is stuck pending

### Changes Made

**Models.swift (TallyFeatureAPIClient)**
- Added static `isoDateFormatter` for performance (review feedback)
- Added computed properties to Challenge:
  - `hasStarted` - uses Calendar.startOfDay for consistent date comparison
  - `isFuture` - inverse of hasStarted
  - `daysUntilStart` - nil if already started
  - `startsInText` - "Starts tomorrow" or "Starts in X days"

**ChallengeCardView.swift**
- New `FutureChallengeBadge` component (takes text string)
- Shows future badge instead of PaceIndicator for future challenges
- Hides quick-add button for future challenges
- Updated accessibility labels

**ChallengeDetailView.swift**
- `futureChallengeCallout` shows when challenge starts
- Hides pace callout, stats grid, burn-up chart, heatmap for future challenges
- Disables "Add Entry" button for future challenges

**ChallengesManager.swift**
- `computeOverallPaceStatus()` now only considers started challenges

### Test Coverage Added

- testChallengeHasStarted_PastStartDate
- testChallengeHasStarted_TodayStartDate
- testChallengeIsFuture_FutureStartDate
- testChallengeStartsInText_Tomorrow
- testChallengeWithInvalidStartDate
